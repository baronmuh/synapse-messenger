## Findings (pre-optimization)

- **Most expensive commands (W=8):** `get_conversation` (RPS 78.5, mean 80.8 ms) and `get_messages` (RPS 83.1, mean 76.4 ms). These are mailbox/conversation reads — priority targets for SQL query optimization.
- **Heavy latency tail on `send_message`:** p50 12.0 ms but p95 170.5 ms / p99 578.4 ms / max 1591.9 ms — check write contention / locking.
- **Heavy tail on `read_message`:** p50 7.6 ms vs p99 251.0 ms (ratio x33).
- **Errors observed (3 scenarios):** all `ConnectionResetError` — connection dropped by the server under high concurrency, never an application error:
  - `sweep:W48:pass1` : 0.170 % (ConnectionResetError x2)
  - `sweep:W64:pass2` : 0.058 % (ConnectionResetError x1)
  - `mode:connexion-par-requete` : 0.048 % (ConnectionResetError x1)
- **Memory:** RSS peaks up to ~600 MiB (W=48) — production Argon2id cost (~64 MiB per concurrent verification). The 2.5 GiB guard was never approached, no aborts.
